# Лабораторная работа 4 — «Автоматический машинный перевод текстов»

**Вариант 1.** Направление перевода — **англо-русский**. Предметные области — научные статьи
по computer science и сочинения по литературе.

Система правилового машинного перевода: анализ английского текста (spaCy), поиск в словаре
на 62 009 статей в PostgreSQL, разрешение многозначности с учётом предметной области,
морфологическая генерация русских форм (pymorphy3) и синтаксический трансфер. Бэкенд на
Python/FastAPI, фронтенд на React 19 + Vite + Tailwind v4, всё в Docker.

## Быстрый старт

```bash
make up
```

Одна команда: собирает образы, поднимает PostgreSQL, применяет миграции, засеивает словарь
и ждёт готовности. Ничего доустанавливать не нужно — словарь лежит в репозитории, модели
скачиваются на этапе сборки образа.

| Что | Где |
|---|---|
| Интерфейс | <http://localhost:8090> |
| API (Swagger) | <http://localhost:8020/api/docs> |
| Готовность | <http://localhost:8020/api/health/ready> |

Порты сдвинуты с обычных (8090 / 8020 / 5434), чтобы не конфликтовать с лабораторными 1–2.
`make help` печатает все команды.

| Команда | Что делает |
|---|---|
| `make up` / `make down` / `make restart` | запуск / остановка / перезапуск |
| `make logs` / `make logs-api` | логи всех сервисов / только бэкенда |
| `make test` | pytest внутри контейнера (176 тестов) |

## Интерфейс

Язык интерфейса — английский. Четыре страницы, на всех неочевидных элементах — подсказки «?».

**Translate.** Ввод текста (вставка, загрузка `.txt`/`.html`, три готовых примера), выбор
предметной области и архитектуры перевода. Результат — полоса статистики и пять вкладок:

1. **Translation** — параллельный текст по предложениям. Наведение на слово подсвечивает
   слово-источник (выравнивание точное, а не оценочное — система правиловая). Кнопка
   *Post-edit* правит перевод предложения; правка уходит в память переводов. Раскрывающийся
   блок «What the rules did» перечисляет выброшенные и вставленные правилами слова с
   причиной.
2. **Words** — *вкладка 1 по заданию*: список слов, упорядоченный по частоте встречаемости,
   с переводом, тегом части речи и его расшифровкой, морфологическими признаками и
   значением из словаря. Сортировка по любому столбцу, фильтры (непереведённые,
   многозначные, выброшенные правилами).
3. **Parse tree** — *вкладка 2 по заданию*: дерево синтаксического разбора выбранного
   предложения (SVG, клик по узлу — полный разбор) и таблица токенов под ним.
4. **Senses** — разбор решений модуля разрешения многозначности: все значения-кандидаты,
   их баллы и вклад каждого сигнала. Кнопка *Use this* закрепляет значение за предметной
   областью навсегда.
5. **Architectures** — тот же текст через прямую и трансферную архитектуры, плюс что
   изменил каждый этап конвейера.

Кнопки **Export .txt** (Unicode-файл с переводом, статистикой, частотным списком и
расшифровкой тегов) и **Print** (печатная вёрстка) закрывают требование о сохранении и
распечатке результатов.

**Dictionary.** Поиск и правка словаря; очередь автопополнения; список закреплённых значений.
**Memory.** Память переводов: просмотр, поиск, проверка предложения на совпадение, импорт/экспорт.
**Help.** Инструкция, описание алгоритмов, справочник тегов и таблицы правил трансфера.

### Две дополнительные фичи

**1. Память переводов с постредактированием.** Подход промышленных CAT-систем: правка
перевода сохраняется как единица памяти; при следующем появлении того же предложения
используется утверждённый перевод (100%), похожего — предлагается с процентом совпадения
(триграммное сходство `pg_trgm`, порог 70%). Страница Memory показывает содержимое памяти,
статистику переиспользования и позволяет проверить любое предложение до перевода.

**2. Разрешение многозначности с учётом предметной области.** Переключатель предметной
области взят прямо из варианта 1. Значение выбирается по шести сигналам с объяснением
каждого, и выбор можно закрепить. Проверяемый эффект: `character` → «персонаж» в литературе
и «знак» в computer science; `network` → «сеть» в CS и «связи» без выбранной области;
`approach` → «подход», а не «заход на посадку»; `computer` никогда не переводится редким
историческим «вычислитель».

Третьим пунктом идёт **сравнение архитектур МП** (вкладка Architectures) — прямой пословный
перевод против трансферного, с пошаговой трассировкой. Это прямая иллюстрация
классификации СМП из методички, поэтому она встроена в основной функционал, а не вынесена
в отдельную фичу.

## Как переводит

```
текст → анализ (spaCy) → лексический трансфер → разрешение многозначности
      → морфологическая генерация (pymorphy3) → синтаксический трансфер → русский текст
```

1. **Анализ.** `en_core_web_md`: предложения, токены, леммы, Universal POS и Penn-теги,
   морфологические признаки, дерево зависимостей. Ничего русского на этом этапе нет.
2. **Лексический трансфер.** Поиск по (лемма, часть речи); многословные единицы
   («machine learning», «point of view») ищутся первыми и самые длинные. Одно обращение к
   базе на документ: все кандидаты собираются заранее.
3. **Разрешение многозначности.** Балл значения =
   `3.0·тематическая метка + 1.2·лексика предметной области + 1.5·пересечение с контекстом
   (Леск) + 1.8·синтаксическое соответствие + 0.6·дистрибутивная близость +
   0.8·порядок в словаре − 2.0·метка чужой области − 2.5·стилистическая помета`.
   Закреплённое пользователем значение перебивает всё.
4. **Морфологическая генерация.** pymorphy3 строит нужную форму; согласование
   протягивается по дереву: прилагательные и причастия берут род, число и падеж у своего
   существительного (включая одушевлённость в винительном), глаголы — лицо и число у
   подлежащего, а в прошедшем времени ещё и род — которого в английском нет вообще.
5. **Синтаксический трансфер.** Артикли, do-support, инфинитивная частица и связка
   настоящего времени выбрасываются. Каждая синтаксическая роль даёт падеж; предлоги
   переопределяют его своим управлением, отдельные глаголы — своим («управлять» +
   творительный). Именные определения и притяжательные уходят за вершину в родительном:
   «network model» → «модель сети», «the author's narrative» → «повествование автора».
   Страдательный залог становится кратким причастием, согласованным с подлежащим:
   «the quality was evaluated by researchers» → «качество было оценено исследователями».

### Известные ограничения

Названы честно, потому что три из четырёх исправляются прямо в интерфейсе:

* **Вид глагола** выбирается по времени — в английском вида нет. Иногда получается
  будущее вместо настоящего, если словарь даёт только совершенный вид.
* **Порядок переводов внутри значения** — лексикографа, а не предметной области: `paper`
  даёт «бумага» раньше «статья». Правится на странице Dictionary, навсегда.
* **Ошибки разбора** на существительно-глагольной омонимии («model studies», «encoder maps»)
  уводят всю структуру предложения.
* **Кореференция** не разрешается, поэтому «его» там, где человек написал бы «свой».

## Структура

```
backend/app/
  main.py              FastAPI, lifespan: загрузка spaCy и pymorphy3
  config.py            настройки, пороги, пути
  state.py             процессные синглтоны языковых ресурсов
  db/models.py         схема: словарь (статья → значение → перевод), закрепления,
                       память переводов, очередь OOV, история переводов
  db/migrations/       Alembic (+ расширение pg_trgm)
  mt/analysis.py       этап 1: разбор английского
  mt/tagset.py         теги трёх наборов и их расшифровка
  mt/lexicon.py        этап 2: поиск в словаре, многословные единицы
  mt/wsd.py            этап 3: разрешение многозначности (доп. фича 2)
  mt/domains.py        предметные области, таксономия меток
  mt/morphgen.py       этап 4: генерация русских форм
  mt/grammar.py        таблицы правил: предлоги, падежи, модальность, местоимения
  mt/transfer.py       этап 5: синтаксический трансфер
  mt/direct.py         прямая архитектура (пословный перевод)
  mt/pipeline.py       сборка конвейера, трассировка этапов
  mt/stats.py          подсчёты и частотный список (вкладка 1)
  mt/tree.py           дерево разбора (вкладка 2)
  services/tm.py       память переводов (доп. фича 1)
  services/enrich.py   автопополнение словаря: Wiktionary, деривация, транскрипция
  services/dictionary.py  CRUD словаря, очередь OOV, закрепления
  services/export.py   Unicode-txt
  api/                 маршруты /api/*
backend/scripts/
  build_dictionary.py  FreeDict TEI → data/dictionary/eng-rus.jsonl.gz
  seed_dictionary.py   JSONL → PostgreSQL через COPY (~8 с)
backend/tests/         176 тестов pytest
frontend/src/
  pages/               Translate, Dictionary, Memory, Help
  components/          вкладки результата, дерево разбора, редактор словаря, примитивы UI
  lib/                 API-клиент, типы, роутер, тема
data/dictionary/       eng-rus.jsonl.gz — словарь, лежит в репозитории
data/samples/          три примера текстов
```

## Данные и лицензии

* **Словарь** — [FreeDict eng-rus](https://freedict.org/) 2025-11-23, CC BY-SA 3.0,
  извлечён из Wiktionary: 62 009 статей, 78 718 значений, 143 402 русских соответствия,
  15 597 многословных единиц. У каждого значения сохранены английское определение и
  тематические метки Wiktionary — именно они делают возможным учёт предметной области.
* **Анализ английского** — spaCy `en_core_web_md` (MIT).
* **Русская морфология** — pymorphy3 + OpenCorpora (MIT / CC BY-SA).
* Автопополнение словаря может обращаться к API английского Wiktionary; отключается
  через `ENRICH_WIKTIONARY_ENABLED=false` в `.env`, тогда работают только офлайн-источники.
