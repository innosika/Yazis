# Лабораторные работы 8 и 9 — «Lector»

**Вариант 1.** Язык — **английский**, предметная область — **научные статьи по computer science**.

Одна система закрывает обе работы:

- **ЛР 8, синтез речи.** Lector читает статьи вслух нейросетевым голосом и подсвечивает
  произносимое предложение и слово.
- **ЛР 9, распознавание речи.** Чтением и приложением управляют голосом: около 40
  операций, их список настраивается, система сообщает, что услышала и что сделала.

**Стек:**
- бэкенд — Python 3.12 / FastAPI;
- фронтенд — React 19 + Vite + Tailwind v4;
- синтез — Kokoro-82M, локально на CPU;
- распознавание — Whisper large-v3-turbo через Groq, запасной вариант — локальная
  Parakeet-TDT 0.6B v3;
- детектор речи — Silero VAD в браузере;
- расширение для Chrome;
- всё в Docker.

## Быстрый старт

```bash
make up
```

При первом запуске `make up` делает три вещи:
1. собирает образы (4–8 минут);
2. один раз скачивает модели речи в том `models` (около 1 ГБ: Kokoro 330 МБ, Parakeet
   670 МБ), со вторым запуском ничего не качается;
3. ждёт, пока голос загрузится и прогреется.

| Что | Где |
|---|---|
| Интерфейс | <http://localhost:8100> |
| API (Swagger) | <http://localhost:8030/api/docs> |
| Готовность | <http://localhost:8030/api/health/ready> |

Порты сдвинуты (8100 / 8030), чтобы не мешать остальным лабораторным.

**Ключ Groq** (бесплатный, <https://console.groq.com/keys>) пишется в `.env` как
`GROQ_API_KEY=…`. Без ключа всё работает локально: распознаёт Parakeet, команды
сопоставляются точно и нечётко, но нет понимания свободных формулировок и ассистента
(explain / summarize).

| Команда | Что делает |
|---|---|
| `make up` / `make down` / `make restart` | запуск / остановка / перезапуск |
| `make logs` / `make logs-api` | логи всех сервисов / только бэкенда |
| `make test` | быстрые тесты: 343 pytest (без моделей) + vitest |
| `make test-all` | плюс тесты на настоящих моделях |
| `make loopback` | проверка голосового пути без микрофона (см. «Результаты») |
| `make lint` | ruff + mypy --strict, eslint + tsc |
| `make extension` | zip расширения для Chrome |
| `make catalog` | заново сгенерировать типизированный каталог команд для фронтенда |
| `make reset-db` | очистить библиотеку и настройки (модели остаются) |
| `make clean` | удалить контейнеры, тома (и модели) и образы проекта |

Ресурсы: в работе около 3 ГБ RAM (голос и распознаватель). Синтезу отдано 6 потоков
CPU, `TTS_THREADS` в `.env`. Образ бэкенда весит 2,8 ГБ, из них около 1,5 ГБ
приходится на CPU-сборку PyTorch и spaCy.

### ЛР 9 — распознавание речи

| Требование | Где |
|---|---|
| Задание списка операций | Settings → **Commands**: 38 встроенных команд. Каждую можно выключить и поменять её фразы на каждом языке. **Свои команды** — макрос из шагов (например, «study mode» = скорость 0.9 + голос Emma + ответ «Study mode on»). Тестер фраз: текстом или **аудиофайлом** |
| Автоматическая реакция с уведомлением | см. ниже |
| Выбор естественного языка | Settings → Listening: **English / Русский / Deutsch / Français**, у каждого свой набор фраз; для синтеза акцент US/UK |

Как система реагирует и что показывает:
- детектор речи слушает микрофон и режет речь на фразы;
- фраза уходит на распознавание, затем сопоставляется с командами, затем выполняется;
- о каждом шаге сообщается:
  - индикатор микрофона: *listening → hearing → recognizing*;
  - строка над плеером: «“slow down a bit” → Speed 0.9×»;
  - звуковой сигнал или голосовой ответ;
  - системное уведомление, если вкладка в фоне;
  - журнал **Activity**: что услышано, какая команда, метод, уверенность, движок,
    задержка.

## Интерфейс

Интерфейс на английском, светлая и тёмная темы, работает от 400 px. Основные части:

- **Library** — недавние документы с прогрессом чтения. Первый запуск открывает
  встроенную статью-пример про устройство TTS; в ней много нотации, на которой
  хорошо видна работа нормализатора.
- **Редактирование.**
  - У каждого документа в библиотеке меню «⋯»: *Rename* (прямо в списке, Enter сохраняет, Esc отменяет), *Edit text*, *Delete* (с подтверждением).
  - Кнопка *Edit* в ридере или клавиша **E** открывают редактор: название, авторы и текст. Разметка простая: `#` / `##` — заголовки, `- ` — пункты списка, `$…$` — формулы, пустая строка — новый абзац.
  - **Ctrl+S** сохраняет, **Esc** отменяет.
  - С несохранёнными правками уйти нельзя без подтверждения.
  - Документ превращается в текст и обратно без потерь: сохранение без правок ничего не меняет, позиция чтения сохраняется.
- **New** — ввод и импорт. Готовые примеры: *Attention Is All You Need*, *LoRA*, *BERT*
  (скачиваются с arXiv на лету).
- **Ридер** — колонка шрифта Literata. Номера разделов висят на полях, формулы
  рендерит KaTeX, справа оглавление.
  - Переключатель ***Spoken form*** показывает под каждым абзацем текст ровно так, как
    его произносит голос: `O(n log n)` → «big O of n log n», `16GB` → «16 gigabytes»,
    `[12]` → пропуск.
- **Плеер** — голос, ⏮ ⏯ ⏭, прогресс, скорость, громкость, микрофон, журнал.
- **⌘K / Ctrl+K** — палитра всех действий с подсказкой голосовой фразы, переход к
  разделам и документам.
- **Хоткеи:**
  - Space — пуск/пауза;
  - ←/→ — предложение, Shift+←/→ — абзац;
  - `[` `]` — скорость;
  - M — микрофон (удерживать в режиме push-to-talk);
  - `?` — список команд.

## Расширение для Chrome

1. `chrome://extensions` → включить *Developer mode* → **Load unpacked** → выбрать
   папку `extension/` (или распаковать `make extension`).
2. Lector должен быть запущен (`make up`).
3. На любой странице выделить текст → нажать ▶ рядом (или правый клик → *Read aloud
   with Lector*, или Alt+R).

Голос, темп и правила чтения берутся из настроек Lector. В popup расширения можно
быстро сменить голос и скорость.

Устройство (Manifest V3):
- **content script** рисует кнопку и мини-плеер в закрытом shadow DOM и сам к серверу
  не обращается;
- **service worker** только маршрутизирует сообщения;
- **offscreen document** делает запросы и воспроизводит звук.

Так запросы к `localhost` идут из контекста расширения с `host_permissions`: нет CORS
страницы и запросов разрешения Chrome Local Network Access. Проверено в Chrome for Testing 151 (Chromium)
на странице Википедии.

## Как синтезируется речь

```
документ → блоки → предложения → единицы воспроизведения (≤ 20 слов)
        → нормализация CS-текста (+ карта смещений) → Kokoro (misaki G2P)
        → таймстемпы слов → выравнивание с исходным текстом → кеш → браузер
```

1. **Импорт.**
   - arXiv: HTML-версия LaTeXML (`arxiv.org/html/<id>`, затем ar5iv, затем PDF). Там
     настоящие разделы и формулы в `<math alttext>`.
   - PDF: PyMuPDF4LLM (порядок чтения в две колонки, без колонтитулов, со склейкой
     переносов).
   - Веб-страницы: trafilatura.
   - Список литературы отрезается.
2. **Сегментация** (`app/text/segment.py`) — правиловая, со списком научных сокращений
   (Fig., Eq., et al., e.g., инициалы, десятичные). Внутри формул не режет. Длинные
   предложения делятся по `;` и `,` на единицы до 20 слов, чтобы первый звук приходил
   примерно через секунду.
3. **Нормализация** (`app/text/normalize/`) — ядро работы. Около 50 правил,
   применяемых по порядку. Каждое правило не переписывает строку, а заменяет **спаны**:
   так сохраняется карта «произносимый символ → исходный фрагмент». Примеры:

   | Написано | Сказано |
   |---|---|
   | `O((V + E) log V)` | big O of V plus E log V |
   | `\frac{QK^{T}}{\sqrt{d_k}}` | Q K transpose over square root of d sub k |
   | `(Vaswani et al., 2017)`, `[3, 5-7]` | пропуск (или «citing 3, 5 to 7») |
   | `16GB`, `120 ms`, `2.7x`, `1e-4` | 16 gigabytes, 120 milliseconds, 2 point 7 times, 1 times ten to the minus 4 |
   | `SQL`, `CNN`, `NASA`, `LaTeX` | sequel, C N N, nasa, lah tek |
   | `Fig. 3b`, `Eq. (2)`, `e.g.` | Figure 3 b, Equation 2, for example |
   | `train_model.py`, `numEpochs` | train model dot py, num epochs |
   | `https://github.com/…` | a link to github dot com |
   | `3.2 Related Work` (заголовок) | Section 3 point 2. Related Work. |

   Встроенный CS-лексикон — около 200 терминов (`app/text/data/lexicon.yaml`). Словарь
   пользователя имеет приоритет.
4. **Синтез** — Kokoro-82M (Apache-2.0), 28 английских голосов.
   - Одна модель, один поток инференса, очередь с приоритетами: сейчас → предзагрузка
     → расширение.
   - Одинаковые запросы объединяются.
   - RTF около 0,3 на CPU: минута речи синтезируется примерно за 20 секунд.
5. **Выравнивание** (`app/tts/align.py`). Токены misaki несут время начала и конца.
   Их позиции в произносимой строке через карту смещений дают исходный фрагмент, так
   что «big O of n log n» подсвечивает весь `O(n log n)`.
6. **Высота тона без изменения темпа:** синтез со скоростью `s/p`, затем ресемплинг в
   `p = 2^(k/12)` раз.
7. **Кеш:** WAV по SHA-256 от модели, версий нормализатора и лексикона, голоса,
   скорости, тона и текста. Повторное чтение отдаётся примерно за 5 мс.

   В браузере единицы стоят на одной временной шкале Web Audio, вперёд
   предзагружаются три. Пауза — это `AudioContext.suspend()`, поэтому тайминги слов не
   сбиваются. Подсветка слова рисуется через CSS Custom Highlight API, без
   перерисовки React.

## Как распознаются команды

```
микрофон → Silero VAD (в браузере) → фраза 16 кГц WAV → Whisper (Groq) | Parakeet (локально)
        → фильтры (галлюцинации, эхо) → нормализация → шаблоны → нечёткое → LLM → действие
```

- **Детектор речи** работает в браузере (onnxruntime-web), на сервер уходят только
  законченные фразы. Конец фразы — после 0,55 с тишины.
- **Распознавание.** Режим Automatic выбирает Groq Whisper, пока ключ есть и лимит не
  исчерпан, иначе локальную Parakeet. На ошибку 429 срабатывает circuit breaker с
  переключением на локальную модель; интерфейс показывает, какой движок ответил.
  Whisper получает короткую подсказку из слов команд.
- **Фильтры:**
  - типовые галлюцинации Whisper («Thank you.»);
  - низкая уверенность;
  - повтор подсказки;
  - **вычитание эха**: слова, которые Lector сам произносил в момент записи,
    вычитаются из распознанного, и сопоставляется только остаток.
- **Сопоставление** (`app/commands/matcher.py`), три ступени:
  1. **шаблоны** со слотами `{number} {section} {voice} {term}` («go to section
     {number}», «explain {term}»); раздел ищется нечётко по заголовкам документа,
     голос — по именам;
  2. **нечёткое** сравнение RapidFuzz (порог 82, во время чтения 90);
  3. **LLM** `openai/gpt-oss-20b` на Groq со строгой JSON-схемой, где команда — enum
     включённых команд или `none`. Выдумать действие модель не может. Включается
     только не во время чтения и для фраз до 12 слов.

  Числительные понимаются на всех четырёх языках: «section three», «скорость
  полтора», «Abschnitt drei», «section trois».
- **Режимы:**
  - **Push-to-talk** (по умолчанию): удерживать кнопку или M, либо коснуться и
    сказать одну команду. Чтение на это время ставится на паузу.
  - **Always listening**: команды слышны всегда. Во время чтения детектор строже,
    распознаёт только локальная модель (квота не тратится), голос приглушается до 20 %,
    как только пользователь начинает говорить.

Ассистент (нужен ключ Groq): «explain {term}» объясняет термин в контексте текущего
абзаца, «summarize» пересказывает раздел. Ответ показывается в карточке и
зачитывается тем же голосом.

## Результаты

**Модульные тесты:** 343 теста pytest проходят за 6 с. Охват:
- нормализатор: около 60 табличных кейсов и инварианты карты смещений;
- сегментатор;
- матчер: 49 фраз на английском, по 10–15 на русском, немецком и французском, 20
  предложений прозы, которые не должны срабатывать;
- числительные;
- фильтры;
- импорт arXiv / PDF / Markdown и круговой путь «документ → текст редактора → документ»;
- API на тестовых движках.

Ещё 3 теста работают на настоящих моделях (`make test-all`).

**Loopback** (`make loopback`): Kokoro произносит 31 команду тремя голосами на трёх
скоростях, фраза отправляется в `/api/voice/recognize` как с микрофона. Локальная
Parakeet, CPU ноутбука:

| Условие | Верно | Точность | Медиана распознавания |
|---|---|---|---|
| Чистая фраза (31 команда × 3 голоса × 3 скорости) | 275 / 279 | **98,6 %** | 240 мс |
| Белый шум, 20 дБ | 88 / 93 | 94,6 % | 235 мс |
| Команда поверх читающего голоса (эхо −20 дБ, как при приглушении) | 74 / 93 | 79,6 % | 263 мс |
| Предложения статьи — не должны быть командами | 20 / 20 | **100 %** | 541 мс |
| Собственный голос Lector во время чтения — должен игнорироваться | 20 / 20 | **100 %** | 234 мс |

Весь прогон — 2,5 минуты, результаты в `/data/loopback-local.json`. Промахи на чистых
фразах — ошибки самого распознавателя: «Read the abstractor» вместо «abstract», пустой
ответ на «Next sentence» в темпе 0.9.

Облачный Whisper (`make loopback ENGINE=cloud`, 16 команд и 5 предложений с паузами
под лимит 20 запросов в минуту): 16 / 16 команд, 5 / 5 предложений проигнорировано,
медиана 338 мс.

## Ограничения

- **Динамики вместо наушников.** Chrome на Linux не вычитает из микрофона звук,
  который играет сама страница. Когда команда наложена на читающий голос, распознаватель
  слышит в основном голос. Loopback даёт 58 % при эхе −12 дБ (`--echo-db -12`) и 80 % при −20 дБ, которые получаются с приглушением.
  Поэтому:
  - по умолчанию режим push-to-talk, он ставит чтение на паузу;
  - в режиме «always listening» голос приглушается, эхо вычитается, а собственный
    голос Lector никогда не запускает команду (тест «own voice» выше);
  - если Lector несколько раз подряд слышит себя, он сам предлагает наушники.
- **Голос читает только по-английски** (вариант 1). Русский, немецкий и французский —
  языки команд.
- **Бесплатный Groq:** 20 запросов распознавания в минуту и 2000 в день; каждая фраза
  тарифицируется как минимум 10 с. LLM — 1000 запросов в день. При исчерпании Lector
  переходит на локальную модель и пишет об этом.
- **PDF** со сложной вёрсткой (таблицы, формулы картинками) читаются хуже HTML-версии
  arXiv. Если статья есть на arXiv, лучше импортировать по ID.
- Расширение сделано для Chrome/Chromium; адрес сервера по умолчанию
  `localhost:8100`.

## Ручная проверка (микрофон, расширение)

1. Открыть статью, нажать *Listen*: подсветка предложения и слова идёт синхронно с
   голосом.
2. Удерживая **M**, сказать «slower» → над плеером «“slower” → Speed 0.9×», звуковой
   сигнал.
3. Коснуться микрофона и сказать «go to section three» → переход к разделу 3.
4. Settings → Listening → Русский; сказать «пауза» → чтение на паузе.
5. Settings → Commands → *New command* «study mode» (Set speed 0.9, Switch voice Emma,
   ответ «Study mode on») → сказать «study mode».
6. Расширение: выделить абзац на Википедии → ▶ → звук, мини-плеер; Alt+R; контекстное
   меню.

